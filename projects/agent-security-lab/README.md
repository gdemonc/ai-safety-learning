# Agent 安全实验室

这个项目是第二套练习项目，用来让你从“RAG 只会回答问题”升级到“Agent 会决定动作并调用工具”的安全场景。

## 练习目标

完成这个实验后，你应该能解释：

1. 为什么 Agent 比普通聊天机器人危险
2. 为什么工具权限边界比回答内容更重要
3. 为什么外部文本和工具输出都可能改变 Agent 的目标
4. 为什么日志里必须记录工具调用链路

## 建议最小能力集

建议你自己实现一个最小 Agent，并且只给 3 个 mock 工具：

- `read_file`
- `search_docs`
- `send_email_mock`

所有工具都应该是本地可控、无真实外部副作用的。

## 建议练习主题

### 1. 直接注入测试

观察用户输入是否会改变 Agent 原始任务。

### 2. 工具输出污染

观察 Agent 是否会把工具返回内容误当成高优先级指令。

### 3. 工具权限最小化

验证 Agent 是否调用了与任务无关的工具。

### 4. 高风险动作审计

记录每次工具调用的：

- 用户问题
- Agent 目标
- 选择的工具
- 工具参数
- 最终结果

## 目录说明

- `app/`：你自己的 Agent 原型代码
- `fixtures/`：本地文件、伪知识库、伪邮件输出
- `prompts/`：测试问题分类
- `notes/`：攻击与防守记录

## 建议实现顺序

1. 先实现一个只会 `search_docs` 的 Agent
2. 再加 `read_file`
3. 最后再加 `send_email_mock`
4. 每加一个工具，就重新做一轮安全测试
